## Правила производительности, найденные измерением

Все найдены измерением на этой сборке Node, все стоили кому-то переписывания:

- **`Map` течёт при вставке никогда не повторяющегося ключа.** ACTR-1 держал
  `Map<id, Actor>` с монотонным счётчиком и `delete` при возврате слота — это
  дало **стабильные ~456 Б/вызов** на всех 5000 раундах (не шум): V8 компактит
  backing store даже когда живых записей не больше одной. Лечится арифметикой
  индексов вместо `Map`. Тот же класс находки, что у PHYS-1 в `grid.js`.
- **`array.length = 0` рвёт backing store массива** — следующая запись
  переаллоцирует. ACTR-1 усекал так плотный список живых на каждом `release()`;
  переписал на вычисляемый `Proxy`-вид над хранилищем, вообще без массива.
- **`Map.prototype.clear()` аллоцирует безусловно**, даже на пустой карте.
  Поэтому `actor.cooldowns` при рецикле слота **не очищается** — и это
  **незакрытый пробел**: как только `skills`/ACTR-9/ACTR-10 начнут туда писать,
  переиспользованный слот унаследует чужие кулдауны. Нужна структура на
  параллельных массивах с ручным счётчиком, а не `Map`. Владелец — ACTR-9/ACTR-10.
- **`Math.hypot` аллоцирует.** Проверено оркестратором независимо на этой сборке
  Node: `Math.hypot(x, y)` — **5.73 байта на вызов**, `Math.sqrt(x*x + y*y)` —
  **0.34**. Нашёл PHYS-2, поймав это в `moveBody`. В любом коде, помеченном
  `Alloc = no` (а это почти вся математика физики, боя и навигации),
  `Math.hypot` использовать **нельзя** — только `Math.sqrt`.

  окажется пустым — начинать надо с этих флагов.
- Playwright уже стоит из `devDependencies` (CORE-1), браузер скачан.

**Рецепт съёмки кадра — воспроизвести за минуты, когда дойдут руки до TEST-3:**

```

```

— **1280×720, это разрешение пиксельного базлайна из `12-testing.md` §6**;

`page.evaluate`** — из разных вызовов восстановление не срабатывает.

## Правило работы с git для сабагентов

Помимо запрета коммитов и пушей: **`git stash` в этом проекте запрещён тоже.**

Причина конкретная, а не формальная. Весь результат тринадцати принятых тикетов
живёт **в рабочем дереве без единого коммита** — восстанавливать нечего и
неоткуда. `git stash` без `-u` захватывает трекнутые файлы **чужих** тикетов;
один сабагент (TEST-2) так и сделал, зацепив `docs/spec/02-api-contracts.md` с
правками RNDR-1 и RNDR-2, и вернул его через `stash pop`. Проверено: файл цел,
ровно три вставки, стек `stash` пуст, потерь нет. Но при обрыве соединения между
`stash` и `pop` (а обрывы в этой сессии уже случались) три строки контракта
исчезли бы молча.

Формулировка для брифов: **никаких `git stash`, `checkout`, `restore`, `clean`,
`reset` — вообще ничего, что трогает рабочее дерево целиком.** Нужно временно
убрать свой файл — переименуй его, а не прячь дерево.

### D-5 — хеш состояния включает **числовые** вторичные ресурсы, а не строку архетипа

`12-testing.md` §7 требует хешировать `id, x, z, life, mana, **secondary**, state,
actionSeq`. Но поля `secondary` на записи `Actor` нет:

- `01-data-model.md:415` — `secondary: 'rage'` лежит на записи **классового
  архетипа** (среди `trees`, `startingItems`, `startGold`) и это **строка**
  `'rage' | 'resonance' | null`;
- `01-data-model.md:286–288` — у `Actor` ресурсы **числовые**: `rage`,

«строка архетипа» отброшено по существу — она константа на весь прогон, в хеше

начислении ярости или резонанса, то есть обесценивает `12.D04` и `12.D07`.

хешировать все три строго безопаснее, чем угадывать активный.

**Обязательство для ACTR-1:** запись `Actor` не должна обзаводиться полем
`secondary` — вторичный ресурс остаётся числовым (`rage`/`resonance`), а строка

### D-1 — `q.maxActors` = 24 / 32 / 44 / 56, ёмкость пула `Actor` — отдельная величина

24/32/44/56. Аннотация `(q.maxActors)` в `01` §11.1 признана опечаткой:
