# Claudo II: Lord of Instruction — план реализации

**Жанр:** Action/RPG в традиции Diablo II — фиксированная камера 3/4,
click-to-move, глубокая итемизация, деревья навыков, один сгенерированный акт.

**Статус:** план. Код ещё не пишется.
**Дата:** 27 июля 2026.

Итог брейншторма — эти пункты закрыты, их не переобсуждаем:

### Не берём

`src/weapons/`, `src/player/` (FPS-контроллер), `src/physics/` (BVH под
пулевую баллистику и рагдоллы — нам нужна дешёвая 2.5D физика),
`src/ai/` (укрытия, перестрелки), `src/world/` (модульный кит зданий под шутер).

**Ключевой вывод из README оригинала**, который переносим в процесс, а не в код:
> «Последовательные проходы с одним владельцем решительно лучше параллельного
> веера». Три раунда по шесть агентов дали +0.46 к оценке и увеличили число
> дефектов; один последовательный проход с одним владельцем — +1.00 и −60%
> дефектов, потому что тонмаппинг, небо и непрямой свет — одна связанная система.

Отсюда правило нашего процесса: **геймплейные подсистемы (items, skills, combat,
ai, nav) параллелятся хорошо — они развязаны событиями. Визуальный проход
(render + materials + sky + fx) делает один владелец последовательно.**

## 3. Архитектура

Контракт для агентов вынесен в отдельный файл — **`ARCHITECTURE.md`** рядом с
этим планом (на английском, как в оригинале: его читают агенты, а не человек).

├── ai              поведение мобов, паки, чемпионы, босс           deps: actors, nav, combat, world

├── fx              партиклы, импакты, декали, свечение лута        deps: render, materials

16 подсистем против 11 в оригинале — но каждая меньше, потому что геймплейная
логика дробится тоньше, чем визуальная.

### Частота симуляции

Оригинал крутит физику на 120 Гц ради баллистики. Нам столько не надо:
**`fixedUpdate` на 60 Гц**. Вся игровая логика — там. `update` только
интерполирует и анимирует. Это даёт воспроизводимость: один сид + один
скрипт ввода = один и тот же результат боя, что критично для балансного
харнесса (§9).

## 4. Геймплейные системы в деталях

### 4.1 Статы и производные величины

Первичные: **Сила (STR)**, **Ловкость (DEX)**, **Живучесть (VIT)**,
**Энергия (ENE)**. За уровень — 5 очков.

```
Жизнь   = base_life  + VIT * life_per_vit  + level * life_per_lvl
Мана    = base_mana  + ENE * mana_per_ene  + level * mana_per_lvl
Стамина = base_stam  + VIT * 1             (бег; опционально в MVP)

Атака (AR)   = 5 * (DEX - 7) + Σ AR от предметов и скиллов
Защита (DEF) = Σ защита экипировки * (1 + бонусы%) + floor(DEX / 4)
```

Таблица классов:

| Класс | base_life | life/VIT | life/lvl | base_mana | mana/ENE | mana/lvl | Стартовые статы (STR/DEX/VIT/ENE) |
|---|---|---|---|---|---|---|---|
| Разоритель | 55 | 4.0 | 2.0 | 10 | 1.0 | 0.5 | 30 / 20 / 25 / 10 |
| Пепельник | 40 | 2.0 | 1.0 | 25 | 2.5 | 2.0 | 15 / 25 / 15 / 35 |
| Рунный клинок | 45 | 3.0 | 1.5 | 18 | 1.75 | 1.25 | 22 / 25 / 20 / 22 |

### 4.2 Боевая математика (по мотивам D2, но без фрейм-брейкпоинтов)

```
Шанс попасть:
  CTH = 200 * (AR / (AR + DEF)) * (alvl / (alvl + dlvl))
  clamp(CTH, 5, 95)                    // заклинания: AR = 0 => всегда попадают

Блок (нужен щит):
  block% = clamp(shield_block * (DEX - 15) / (2 * clvl), 0, 75)

Урон:
  raw   = roll(minDmg, maxDmg) * (1 + ED%/100)
  raw  *= 1 + str_bonus       // STR/100 для одноручного, STR/75 для двуручного
  crit  = roll < critChance ? critMult : 1        // «смертельный удар»
  phys  = raw * crit
  phys -= flat_damage_reduce
  phys *= (1 - damage_reduce% / 100)

  elem_i = roll(min_i, max_i) * (1 + skill_elem%/100)
  elem_i *= (1 - clamp(resist_i, -100, 75) / 100)

  total = phys + Σ elem_i
```

Скорость атаки — непрерывный множитель `1 / (1 + IAS/100)` на длительность
анимации, без брейкпоинтов D2 (это упрощение сознательное: брейкпоинты — артефакт
25-фпс движка 2000 года, воспроизводить их не нужно).

Восстановление после удара (hit recovery): при получении >5% макс. жизни за удар
актор входит в стан на `0.4 / (1 + FHR/100)` сек.

Прочность предметов, ремонт у торговца — есть (дёшево, добавляет петлю возврата
в город).

### 4.3 Классы и деревья навыков

Формат: 2 ветки × 5 навыков = **10 навыков на класс, 30 всего**. Каждый навык
качается до 20 очков. Требования по уровню персонажа и по вложенным очкам в
предшественника. Синергии: навык A даёт +X% к эффекту навыка B за уровень.

### 4.4 Итемизация — ядро игры

#### Модель данных

```js
// src/items/data/bases.js
ItemBase = {
  id, name, class: 'weapon'|'armour'|'jewelry', slot,
  tier: 'normal'|'exceptional'|'elite',
  reqLevel, reqStr, reqDex,
  invW, invH,                      // размер в сетке инвентаря
  weapon:  { minDmg, maxDmg, speed, twoHanded, range },
  armour:  { defMin, defMax, blockBase },
  allowedAffixTypes: ['weapon.melee', ...],
  dropWeight,
}

// src/items/data/affixes.js
Affix = {
  id, kind: 'prefix'|'suffix', group,      // из одной группы — только один аффикс
  nameRu, alvl,                            // минимальный item level
  appliesTo: ['weapon', 'armour', 'ring'],
  mods: [{ stat: 'ed'|'flatFire'|'life'|'ar'|'res.fire'|..., min, max }],
  weight,
}
```

#### Алгоритм дропа (порядок фиксирован ради детерминизма)

1. Монстр умирает → выбирается **treasure class** по его типу и уровню зоны.
2. Ролл «есть ли дроп» (веса `nodrop` растут при малом числе игроков — у нас
   один, поэтому просто константа).
3. Выбор базы: фильтр `reqLevel ≤ ilvl`, взвешенный по `dropWeight`.
4. Ролл качества: **уник → редкий → магический → отличный → обычный**.
   Шанс каждого уровня масштабируется от `(ilvl − mlvl)` и от Magic Find.
5. Число аффиксов: магический — 1 префикс + 1 суффикс (минимум один);
   редкий — 1–3 префикса и 1–3 суффикса, всего 2–6.
6. Пул аффиксов фильтруется по `alvl ≤ ilvl`, по типу базы, и по уже занятым
   группам. Выбор взвешенный.
7. Значение каждого мода роллится в `[min, max]`.
8. Имя: магический — «префикс + база + суффикс»; редкий — два слова из
   отдельного пула существительных («Погибель Праха»); уник — своё имя.

`ilvl` предмета = уровень монстра (+2 для чемпиона, +3 для уника).

#### Редкости и цвета

| Редкость | Цвет | Особенность |
|---|---|---|
| Обычный | `#c8c8c8` | без аффиксов |
| Отличный (superior) | `#c8c8c8` | +5..15% защиты или урона |
| Магический | `#6a7bff` | 1–2 аффикса |
| Редкий | `#ffe066` | 2–6 аффиксов, нужно опознание |
| Уникальный | `#c8973f` | фиксированный набор модов с роллами, нужно опознание |

**Опознание** — свиток из города, как в D2. Неопознанный предмет показывает
только базу. Дешёвая механика, сильно добавляет петлю «сходил — вернулся».

#### Уники MVP (8 штук)

По одному на слот + два оружейных, каждый с одной ломающей правила модой
(например, «Пепельный венец» — заклинания стоят −25% маны, но −40% макс. жизни).

#### Инвентарь

Сетка **10×4**, укладка прямоугольников. Слоты экипировки: голова, торс, руки,
ноги, оружие, щит/второе оружие, пояс, амулет, 2 кольца. Пояс — 4 быстрых слота
зелий на клавишах. Сундук в городе — 10×8, общий для всех персонажей.

**Иконки предметов генерируются процедурно**: каждая база имеет функцию
рисования на OffscreenCanvas (силуэт + материал + тинт по редкости + рамка).
Это удовлетворяет правилу «ноль ассетов» и даёт бесплатную вариативность.

### 4.5 Монстры и AI

#### Бестиарий

| Моб | Роль | Поведение |
|---|---|---|
| **Костяной ратник** | ближний пехотинец | сближается, бьёт, иногда блокирует щитом |
| **Стая падальщиков** | рой | 6–10 быстрых слабых, окружают, разбегаются при потерях |
| **Пепельный лучник** | дальний | кайтит, отходит при сближении < 6 м |
| **Шаман праха** | саппорт | воскрешает павших ратников, баффает скорость. Приоритетная цель |
| **Молотобоец** | тяжёлый | медленный, огромный урон с виндапом 1.2 сек и телеграфом на земле |
| **Пузырь-ползун** | камикадзе | бежит и взрывается ядовитым облаком |

#### Чемпионы и уники

Тот же меш, другой стат-блок и аффиксы:
- **Чемпион** (синяя аура): ×2.5 жизни, ×1.5 урона, +1 аффикс.
- **Уникальный** (золотая аура, имя над головой): ×5 жизни, ×2 урона,
  3 аффикса, свита из 3–5 миньонов, гарантированный магический+ дроп.

Аффиксы мобов: `Огненный` (взрыв при смерти), `Молниевый` (заряды),
`Ледяной` (замедляющая аура), `Очень быстрый`, `Очень сильный`, `Каменная кожа`,
`Проклинающий`, `Аура вампиризма`, `Мультивыстрел`.

#### AI

Конечный автомат: `idle/wander → alert → chase → attack(windup/active/recovery)
→ reposition → death`. Восприятие: радиус + прямая видимость по nav-сетке.
Пак-логика: мобы одного пака делят «агро-облако» — задел одного, подтянулись все.
Разделение (separation) не даёт слипаться в точку.

Бюджет: **перепланировка A* максимум для N мобов за кадр** (кольцевая очередь),
остальные идут по flow-field к игроку. При >40 активных мобов — все на flow-field,
A* только для отошедших от толпы.

#### Босс: **Мольгрим, Первый Наставник**

| Фаза | Порог | Паттерны |
|---|---|---|
| I | 100–60% | размашистые удары с телеграфом, призыв 4 ратников каждые 20 сек |
| II | 60–25% | расходящиеся огненные кольца (надо уходить в разрывы), рывки |
| III | <25% | телепорты, метеорный дождь, аура выжигания маны −8/сек |

### 4.6 Мир и генерация

#### Город — «Последний Оплот» (авторская планировка, ~60×60 м)

NPC:
- **Каменотёс Верен** — торговец: зелья, свитки, базовые предметы, скупка, ремонт.
- **Ткачиха Рун Иса** — свитки опознания, гнёзда/руны (задел на будущее).
- **Хранитель Сундука** — стеш 10×8.
- **Наставница Кайра** — квестодатель.
- Портал в зону + точка возврата городского портала.

#### Боевые зоны (генерируются по сиду)

```
seed = hash(worldSeed, zoneId, runIndex)
```

1. **Пепельные Пустоши** — открытая, 96×96 м, сетка 4×4 ячейки по 24 м.
   Алгоритм: случайное блуждание от входа к выходу («хребет»), 2–4 тупиковых
   ветки с сундуками/уником, каждая ячейка получает тип декорации
   (поле, роща мёртвых деревьев, руины, овраг, лагерь мобов).
2. **Кости Предела** — подземелье, генератор «комнаты + коридоры»
   (12–18 комнат, BSP-разбиение, гарантированная связность, тупики с лутом).
3. **Алтарь Наставления** — арена босса, планировка фиксированная,
   генерируется только вход и декор.

**Гарантии генератора** (проверяются харнессом `tools/mapgen.mjs`):
путь вход→выход всегда существует; босс всегда достижим; плотность мобов
в пределах ±20% от целевой; нет замкнутых зон с лутом.

Навигация: сетка 0.5 м, флаги `walkable / blocked / hazard`, строится из
коллайдеров сразу после генерации, версионируется (`zone:ready` несёт
`navVersion`, чтобы `ai` инвалидировал пути).

### 4.7 Квест и петля сессии

**Квест: «Слово, что не гаснет».** Кайра просит принести Первую Табличку из
Алтаря Наставления. Награда: выбор одного из трёх предметов + **постоянный
+1 ко всем навыкам** (как квестовые награды в D2).

Петля: город (экипировка, зелья, стеш) → портал → Пустоши (мобы, лут, паки) →
Кости Предела → Алтарь → босс → городской портал → продать/опознать/раскачать →
заново с новым сидом на большей сложности.

Три уровня сложности (Normal / Nightmare / Hell — переименуем в
**Наставление / Испытание / Отречение**): множители жизни/урона мобов,
штрафы к резистам игрока, +item level дропа.

### 4.8 Сохранение

`localStorage`, JSON, ключи `claudo2.save.v1.char.<slot>` и `claudo2.save.v1.stash`.
3 слота персонажей. В сейве: класс, уровень, опыт, распределение статов и
навыков, инвентарь/экипировка (полное состояние предмета с роллами), пояс,
золото, прогресс квеста, сложность, worldSeed. **Версионирование схемы
обязательно с первого дня** — миграции `v1 → v2` пишутся сразу, иначе каждый
балансный правк ломает чужие сейвы.

## 5. Рендер и арт-дирекция

Стиль: **мрачное готическое фэнтези, сумеречная палитра**, читаемость важнее
красивости — под камерой 3/4 на экране до 60 объектов.

- Камера: перспективная, FOV 35°, pitch 52°, дистанция 22 м, плавное следование
  за игроком с зоной нечувствительности; лёгкий сдвиг к курсору (peek).
- Свет: направленный «луна» + ambient из IBL + точечные источники (факелы,
  заклинания, свечение лута) под жёстким бюджетом слотов (см. ловушку в
  ARCHITECTURE.md).
- Тени: 2–3 каскада, дистанция 40 м — камера близко, дальние каскады не нужны.
- Пост: bloom (рарные предметы должны светиться), GTAO, лёгкий виньет,
  процедурный grade LUT, AgX. **TAA под вопросом** — при почти статичной камере
  дешевле SMAA; решаем замером.
- Персонажи: процедурные скелеты (bone rig, собранный кодом) + скиннинг на
  примитивах; анимации — процедурные (IK-шаги, спринговые оверлеи, поза-микс),
  не запечённые клипы. Это самый рискованный пункт плана — см. §10.
- Экипировка визуально отражается: 4 слота меняют геометрию/материал персонажа
  (шлем, торс, оружие, щит). Не 20 — четыре достаточно для «вижу свой билд».

Бюджеты производительности (цель): **60 fps @1080p DPR1**, ≥45 fps @DPR2 на
Apple silicon, ≤150 draw call, ≤2.5M треугольников, 0 компиляций шейдеров
во время игры (prewarm).

## 6. UI / HUD

DOM+CSS оверлей поверх канваса, всё анимируется интегрированием от `dt`
в `lateUpdate` (никаких CSS-переходов — иначе харнесс недетерминирован).

- Нижняя панель: шар жизни (лево), шар маны/ресурса (право), хотбар 1–4,
  пояс зелий, полоса опыта.
- Верх: полоса жизни цели + имя/аффиксы (для чемпионов и босса — отдельная
  жирная полоса).
- Всплывающие цифры урона (пул, без аллокаций), крит выделен.
- Инвентарь: CSS-grid 10×4, drag&drop на pointer-events, подсветка валидной
  укладки, ЛКМ по зелью — выпить.
- Тултип предмета: базовые статы, аффиксы построчно, требования красным если
  не хватает, сравнение с надетым (Ctrl).
- Дерево навыков: DOM + SVG-линии связей, показ требований и синергий.
- Миникарта: отрисовка nav-сетки в canvas 2D, оверлей — как в D2 (Tab).
- Метки лута на земле (Alt) — цвет по редкости, это часть узнаваемости жанра.

Язык интерфейса: **русский** по умолчанию, строки вынесены в `src/ui/i18n.js`
(один объект, без библиотек), английский — вторым словарём.

## 7. Аудио

Web Audio, ноль файлов. Слои:
- **Оружие/удары**: шумовой всплеск через band-pass + короткий тональный «звон»

- **Магия**: огонь — фильтрованный шум с разверткой; молния — импульс + резонанс;

- Спатиализация HRTF, реверб-свёртка (импульс генерируется кодом),
  приглушение при паузе.

## 8. Дев-харнесс

Порт из оригинала:

| Инструмент | Что делает |
|---|---|
| `tools/capture.mjs` | скриншот именованного «шота» через GPU headless Chromium |
| `tools/baseline.mjs` | воспроизводимый набор шотов, каждый в изолированной странице |
| `tools/imagediff.mjs` | попиксельный гейт, ненулевой exit при любом сдвиге |
| `tools/profile.mjs` | профиль кадра при реальном DPR, p50/p95/p99 + атрибуция хитчей |
| `tools/playtest.mjs` | скриптованный прогон: пройти зону, убить N мобов, не упасть |

**Новое, специфичное для ARPG** — и это самая ценная часть плана:

| Инструмент | Что делает | Зачем |
|---|---|---|
| `tools/lootsim.mjs` | 200k дропов headless, гистограмма редкостей/аффиксов/итем-левелов | ловит сломанные веса до того, как в игре «ничего не падает» |
| `tools/balance.mjs` | headless-бой: билд × волна мобов × уровень сложности → TTK, выживаемость, DPS | баланс цифрами, а не «на глаз» |
| `tools/mapgen.mjs` | 200 сидов → PNG-сетка планировок + проверка связности/плотности | ловит недостижимого босса и пустые карты |
| `tools/save-fuzz.mjs` | генерация сейвов всех версий схемы → проверка миграций | сейвы не ломаются между правками |

Все четыре гоняются **без браузера** — поэтому §3 требует, чтобы игровые данные
и математика не зависели от `three` и от DOM. Это архитектурное требование, а не
пожелание: `combat`, `items`, `skills`, `nav` и генератор карты должны
импортироваться в Node напрямую.

## 9. Этапы работ

Каждый этап заканчивается проверяемым критерием. «Готово» = критерий выполнен и
`npm run build` + `tools/capture.mjs` проходят.

| # | Этап | Содержание | Критерий приёмки |
|---|---|---|---|
| **M0** | Каркас | Порт `core/*`, vite, three, пустая сцена, камера 3/4, плоскость, капсула ходит по клику | `npm run dev` — управляемый болван; `capture.mjs` даёт кадр; `build` зелёный |
| **M1** | Мир и навигация | `physics` (2.5D касты, расталкивание), `nav` (сетка+A*+сглаживание), `world` со статичной тестовой картой и переходами | Персонаж обходит препятствия, не застревает в углах; путь строится за <1 мс на 96×96 м |
| **M2** | Акторы и бой | `actors` (стат-блок, скелет, процедурная анимация), `combat` (вся математика §4.2), один тестовый моб, урон, смерть, полоски жизни | Формулы покрыты юнит-тестами в Node; моб бьёт, игрок умирает и воскресает |
| **M3** | Лут и инвентарь | `items` целиком: базы, аффиксы, роллы, treasure class, дроп на землю, подбор, сетка-тетрис, экипировка, тултипы, опознание, торговец | `lootsim.mjs` даёт ожидаемое распределение; предмет можно подобрать, опознать, надеть, и статы меняются |
| **M4** | Классы и скиллы (ядро) | `skills` + `player`: 3 класса, по 3 стартовых навыка, ресурсы (ярость/мана/резонанс), хотбар, снаряды, AoE, кулдауны | Каждым классом можно пройти тестовую комнату; резонанс Рунного клинка работает как задумано |
| **M5** | Зоны и бестиарий | Генератор Пустошей и подземелья по сиду, 6 типов мобов, паки, чемпионы/уники с аффиксами, спавн по уровню зоны | `mapgen.mjs` — 200/200 сидов связны; зона проходится от входа до выхода |
| **M6** | Город, квест, мета | Город с 4 NPC, портал, сундук, квест «Слово, что не гаснет», босс Мольгрим (3 фазы), `save` с версионированием, экран создания персонажа | **Игра проходится от создания персонажа до убийства босса и получения награды.** Это первая играбельная версия |
| **M7** | Полные деревья и уники | Оставшиеся 7 навыков на класс, синергии, 8 уникальных предметов, 3 уровня сложности, respec-свиток | `balance.mjs`: ни один билд не выбивается по TTK больше чем в 2× от медианы |
| **M8** | Визуальный проход | **Один владелец, последовательно:** материалы → свет/небо → FX → пост. Экипировка на модели, телеграфы атак, свечение лута | Адверсариальный критик: читаемость 8/10, ни одного «плоского» материала; кадр сравним с современным ARPG |
| **M9** | Аудио, перф, полировка | Синтез всех звуков, prewarm, оптимизация, финальный pixel-gate, hit-stop, экранные импульсы, баланс по данным | 60 fps @1080p; 0 компиляций шейдеров во время игры; `playtest.mjs` проходит 10 прогонов подряд |

Ориентировочный объём: **25–35k строк** — примерно половина оригинала, потому
что render/materials/sky/fx переиспользуются, а не пишутся заново.

### Как распараллеливать

- **M1–M7** — можно веером: подсистемы развязаны событиями, каждый агент владеет
  своей папкой. Хорошо параллелятся пары: (`items` ‖ `skills`), (`nav` ‖ `ai`),
  (`ui` ‖ `save`).
- **M8** — **только последовательно, один владелец.** Это прямой урок из
  README оригинала: тонмаппинг, свет, небо и материалы — одна связанная система,
  и параллельные агенты ломают допущения друг друга.
- **M2 и M4** — критический путь, всё остальное от них зависит; делать первыми
  и не параллелить между собой.

## 10. Риски

| Риск | Вероятность | Митигация |
|---|---|---|
| **Процедурная анимация персонажей** — самый рискованный пункт. Скелет+скиннинг кодом, без клипов | Высокая | Начать с грубого рига в M2 и итерировать. Фолбэк: спрайт-билборды, отрендеренные из процедурных мешей в offscreen на старте |
| **A* на 60+ мобах** проседает | Средняя | Flow-field к игроку как основной режим, A* по кольцевой очереди с бюджетом на кадр |
| **Детерминизм ломается** от UI/асинхронности | Средняя | Один rng-поток на подсистему, фиксированный порядок роллов, гейт `imagediff` + `balance.mjs` с зафиксированным сидом в CI |
| **Баланс лута** — «падает мусор» или «падает всё» | Высокая | `lootsim.mjs` с первого дня M3; веса — данные, не код |
| **Сотни предметов на земле** убивают перф | Средняя | Пул + инстансинг + бюджет `groundItemBudget`, старые дропы истлевают |
| **Читаемость** тонет в FX | Средняя | Правило в ARCHITECTURE.md: цвета редкости и телеграфы атак не перекрываются партиклами; отдельный шот в baseline «плотный бой» |
| **Разрастание объёма** | Высокая | Жёсткое правило: ни одного нового навыка/моба/предмета вне списка выше до M7 |

## 11. Открытые вопросы (не блокируют старт)

1. Мультиплеер — нет и не планируется в MVP. Архитектура событий это не

4. Стамина/бег — заложена в статах, включаем только если бой без неё окажется
   вялым.
5. Публикация: статический билд на GitHub Pages — работает, потому что нет
   бэкенда и нет внешних ассетов.

## 12. Первый шаг

Как только план утверждён — **M0**: инициализировать репозиторий, скопировать
`core/`, `tools/`, `vite.config.js` из Claude-of-Duty с сохранением MIT-нотиса,

клику под камерой 3/4». Дальше M1 и M2 по критическому пути.
